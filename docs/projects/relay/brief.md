# Project 03 — RELAY

Four small models race along a track of puzzles. Any of them may hand a stage to **the anchor** — one shared frontier model — but every escalation drains a pool the whole table draws from, and nobody is ever told which stages are hard.

The game is one decision, repeated: *can I do this myself?*

## What it demonstrates

| Topic | How RELAY covers it |
|---|---|
| **Edge agent** (topic 9, the last unclaimed architecture) | The runners are small open-weight models on local hardware. No API key, no vendor, no network — the framework has to bind to a process on your machine |
| **Escalation / fallback** (topics 4, 5) | Escalating is a model swap under a budget. The matrix rows that have been `—` since day one — cost attribution, retry/backoff/fallback, rate limiting — are what this game is made of |
| **Cost analysis** | Cost is the currency, not the invoice: the quota *is* the scoreboard, and spending it is a move against the other runners |
| **Inference analysis** | Local versus hosted on the same model, cold start included, measured beside a game that does not depend on the measurement |
| **LLM evals** | Ground truth again, and a sharper score than either earlier game: escalation precision and recall against a difficulty the runner was never shown |

## Why a race

The [vision](../../vision.md) argues nobody finishes a tutorial about document summarisation, and [ADR-0010](../../decisions/adr-0010-project-two-alibi.md) rejected a retrieval quiz for exactly that. A benchmark harness that measured "when does the small model need help?" would be the same tutorial with a scoreboard.

So the measurement is the game. Escalating is not instrumentation, it is a move that costs your rivals something, and a runner that escalates well finishes ahead of one that doesn't — [measurably, by about two to one](game-rules.md#does-the-escalation-decision-actually-matter).

## The track

Ten stages, three families — arithmetic `chain`, Caesar `cipher`, constraint `order` — each on a three-step difficulty ladder, all generated deterministically from the seed with the answer known by construction.

Every stage carries a tier. **No runner ever sees it.** Tiers are shuffled across the track so position leaks nothing, and they are revealed only in `game_ended`, which is what lets the eval score every escalation decision against the truth without a judge.

## The anchor — a model, not an agent

Escalation swaps the model for one call and hands the answer straight back. There is no sub-agent, no consultation, no tool.

That is deliberate, and it is what separates RELAY from ALIBI: the [archivist](../alibi/brief.md#the-archivist--agent-as-tool) is a specialist you *ask*, so its cost is a conversation. The anchor is a model you *become* for one call, so its cost is one invocation. Keeping them apart keeps the finding clean — RELAY measures what escalation costs, not what a sub-agent costs.

## What carries over from LUDO and ALIBI

Everything that isn't the two new things, deliberately:

- the shared event stream ([ADR-0003](../../decisions/adr-0003-shared-event-stream.md)) and a UI that consumes only it ([ADR-0007](../../decisions/adr-0007-ui-alongside-first-stack.md))
- one engine per language, held together by conformance vectors over generated bytes ([ADR-0002](../../decisions/adr-0002-engine-per-language.md)) — a discipline ALIBI already proved on a corpus
- framework-native harnesses over a behavioural contract ([ADR-0008](../../decisions/adr-0008-framework-native-harness.md))
- seat rotation ([ADR-0006](../../decisions/adr-0006-seat-rotation.md)), with lanes in place of colours
- shared verbatim prompts, no per-stack edits
- lenient in-fiction guardrails ([ADR-0004](../../decisions/adr-0004-structural-guardrails.md)) — a note that lies about a stage's difficulty is cunning, not an attack
- a deterministic-first eval, judge optional

A reader who understood either earlier project should navigate this one without re-learning anything.

## Scoring

Deterministic, and no judge is needed — the same property ALIBI established, applied to a sharper question. Because `game_ended` reveals every tier, the eval can ask of each escalation: *was this stage actually hard?* Precision and recall against the sealed tier, plus efficiency (stages cleared per quota unit) and the race result itself. See [evaluation](evaluation.md).

## Scope boundaries

Out, on purpose — this project already carries two hard things:

- **Negotiation.** One public note per turn is the entire channel, as in ALIBI ([question 22](../../open-questions.md)).
- **Compaction and session persistence.** A stage prompt plus a short history does not outgrow a window, and inventing pressure to exercise a primitive would be dishonest.
- **Bidding or stealing quota.** A real game, and a third hard thing.
- **Wall-clock racing.** Recorded, never decisive — see [engine design](engine-design.md#why-ticks-and-not-milliseconds).

## Status

Built at the scripted tier and benched. Live play needs an Anthropic key for the anchor and a local model runtime for the runners — **no undecided model id blocks it**, which is what makes RELAY the first project in this repo that could produce a live number. Open: [question 25](../../open-questions.md) is answered by the bench; [question 26](../../open-questions.md) (which small models, hosted how, what to pin) is the live-tier gate.
